Dependency Injection

Dependency Injection (DI) is a design technique where an object does not create its own dependencies.
Instead, those dependencies are provided (“injected”) from the outside.
Spring’s IoC container is the component that creates objects, connects them together, and manages their lifecycle.
Spring Boot uses the same Spring DI mechanism; it mainly simplifies bootstrapping and bean configuration through component scanning, autoconfiguration and sensible defaults.

Spring Security

Spring Security in web applications (turned on by default in SB):
@EnableWebSecurity for MVC
@Bean public SecurityFilterChain securityFilterChain(HttpSecurity http) {
	http
		.authorizeRequests()
		.antMatchers("/admin/**").hasRole("ADMIN")
		.antMatchers("/user/**").hasAnyRole("ADMIN", "USER")
		.antMatchers("/bober/**").hasAuthority("ROLE_BOBER")
		.antMatchers("/bober-user-admin/**").hasAllAuthorities("A_BOBER", "A_USER", "A_ADMIN")
		.antMatchers("/anonymous*").anonymous()
		.antMatchers("/login*").permitAll()
		.anyRequest().authenticated();
}
@Bean public SecurityFilterChain securityFilterChain(HttpSecurity http) {
	http
		.authorizeHttpRequests( (authorize) -> authorize
			.requestMatchers(HttpMethod.GET).hasAuthority("read")
			.requestMatchers(HttpMethod.POST).hasAuthority("write")
			.requestMatchers("/resource/**").hasAuthority("USER")
			.anyRequest().denyAll())
		.httpBasic(Customizer.withDefaults()); // for Http header "Authorization: Basic Base64EncodedValueXYZ==" with 'user:password' encoded value
}
The order of the antMatchers() elements is significant; the more specific rules need to come first, followed by the more general ones. In other words more strict rules should come first.
org.springframework.security.config.annotation.web.configurers.AuthorizeHttpRequestsConfigurer.AuthorizedUrl
hasRole() and hasAuthority() methods differ in that hasRole does not require "ROLE_" prefix. Roles are a subset of Authorities
@EnableWebFluxSecurity for reactive model
@Bean public SecurityWebFilterChain securityFilterChain(ServerHttpSecurity http)
Several security configurations can be set in the same time.
Can be separated using @Profile
or using securityMatcher(..) and in case of non @RestController mappings (Custom servlets, H2-Console etc) - use AntPathRequestMatcher in addition.
Also use @Order(1) for method ordering.
Lambda DSL allows to get rid of an and() concatenation method, when building SecurityFilterChain from HttpSecurity.

CSRF

Should be turned off for stateless apps (REST), but not for session authenticated apps. 
@Bean public SecurityFilterChain securityFilterChain(HttpSecurity http) {
	// http.csrf().disable(); // Deprecated
	http.csrf(csrf -> csrf.disable()); // Actual
	http.csrf(AbstractHttpConfigurer::disable); // Actual
	http.sessionManagement(configurer -> configurer.sessionCreationPolicy(SessionCreationPolicy.STATELESS)); // SessionManagementConfigurer<H extends HttpSecurityBuilder<H>>
}
